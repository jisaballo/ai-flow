# ai-flow hooks

Optional Claude Code hooks that enforce the ai-flow guardrails. Copy them to
`~/.claude/hooks/` (the installer does this) and register them in
`~/.claude/settings.json` (merge `settings.hooks.json` into your `hooks` key).

| Hook | Event | What it does |
|------|-------|--------------|
| `check-state-size.sh` | Stop + UserPromptSubmit | ai-flow guardian, **coordinator checkout only**. Six reports, and they do not all block. **Five refuse**, each having a remedy the operator can complete in the turn it is raised: `STATE.md` carrying closed-work narrative outside its two sanctioned records — the roster table and `## Quick Tasks Completed`, both exempt because the guard reads narrative prose and never a table row; `BACKLOG.md` carrying more than 3 session-close changelog entries; and each of the three unreadable-input cases below. **One is a note that never blocks** — `BACKLOG.md` over its size budget, now **8,000 words** with a firmer threshold at **15,000** rather than a line count that could not see prose: one entry is one line however long it is, so the ledger measured 27% of its old 300-line cap while holding 10,118 words. Its breach is a note because its remedy is *not* bounded — the largest cause, open task rows written as essays, was 71% of that ledger and has no prune at all. **The two buckets are two events** (see `## Which channel reaches whom`): the refusals run at `Stop` on stderr with exit 2; the note runs at `UserPromptSubmit` and carries both halves in one object, because the sweep it asks for is the model's to do. The merge that used to carry the note out on a blocker's stderr line is gone with the run that needed it. The note speaks **once per session per threshold**, its own text serving as the mark and read back only out of the harness's own delivery records — never a free-text search of the transcript, which the engine's own conformance suite would self-silence by holding the mark verbatim. The exception that used to qualify this is gone with the stderr merge: every delivery of the note is now recorded, so *once per threshold* is true rather than approximately true. The reader refuses a path that is not a regular file without opening it — a named pipe would otherwise block until a writer appeared — and reads a bounded tail rather than the whole transcript from the start, at the honest cost that a mark older than the tail reads as unspoken and the note is repeated once. It fails towards speaking, which is the direction every part of this mark is built to fail in. It reports **at most once per request**: the payload says whether the stop is one the harness is re-delivering after a refusal, and on a re-delivery every report stays quiet rather than turning one refusal into a loop. The suppression field is **parsed**, never matched as text, so a truncated payload is absent input and absent input reports — the one field where a text match could be read as a false all-clear. The **event** is the documented exception and only where there is no parser at all: it is matched as text there, because the two fail in opposite directions and a misread event costs a report arriving at the next turn rather than a report silently not arriving. A payload that arrives and cannot be placed refuses nothing and says everything, on the channel that does not block; where `python3` is unavailable nothing is suppressed and the guard behaves as it did before — the noisy direction, which is the safe one. Exits immediately in a linked worktree: the ledger there is a copy the coordinator owns. An `.ai-flow/` that is **absent** is the designed no-op, so the hook is safe to install globally; one that exists but **cannot be read** — the directory itself, `STATE.md`, or `BACKLOG.md` — is refused and named, because an unreadable ledger reported as clean is the one verdict this guard must never give. |
| `diff-size-guard.py` | Stop + UserPromptSubmit | The Diff Size Guardrail, two ceilings: the **step** (uncommitted work >150 added lines) and the **task** (>400 added lines on this branch since its base — commits included, so committing no longer hides growth). Measured in the checkout it runs in, so a worktree is judged on its own branch. Both **ceilings** count **added lines only**: deletions are cheap to review and the direction to reward, and counting them as growth had the brake answering a commit that removed 250 net lines with a measurement of 398. The note is the exception and keeps net growth — it asks whether the change *grew* the file, so a trimmed one draws nothing, and the number it reports is the file's own line count rather than any diff total. Three kinds of file are not counted, none of them code somebody wrote: test suites across stacks (JS/TS, Kotlin, Swift, Java, C#, Python, Go, Ruby, `test/`-style directories); everything under the repository's own `.ai-flow/`, anchored at the root so a shipped `template/.ai-flow/` still counts; and dependency lockfiles (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `Cargo.lock`, `poetry.lock`, `Gemfile.lock`), which the hook names itself rather than reading from the project layer — they are universal filenames, not one project's convention. With no resolvable base branch, only the step ceiling applies. Where the base **is** a remote-tracking ref the task report names it in short form and states the total as work not yet published — one task grown large or several already finished — instead of ordering a split the measure does not support. **And one note, which never blocks**: a non-test file the change has **grown** past `large_file_lines` (a top-level key in `.ai-flow/project.yml`, default 1,000) is named with its line count — *decompose before adding*. Judged over the task diff's files plus untracked ones; a trimmed large file draws nothing. It runs at `UserPromptSubmit` and carries both halves in one object (see `## Which channel reaches whom`), the model being the actor asked to decompose; the ceilings keep `Stop`. The acknowledgement record is shared by both halves and each run marks **only what it delivered** — a run that marked the other half's key would silence a message nobody had read. All three speak **once, then again only after another step's worth of growth**, out of one record in the git dir — one `count<TAB>key` line each. Every key carries the **scope its own measure resets on**, and that is the difference between saying something once and stopping saying it: the step's scope is the commit the checkout is on, so a commit re-arms it; the task ceiling's and each file note's is a fingerprint of the checkout's **open task set**, so a task opening or closing re-arms them. Entries out of scope are dropped when the record is rewritten, which is also what makes a line written before scopes existed inert — ignored, never migrated. The step arm had no acknowledgement at all and produced 80 of the 81 firings measured across this engine's own transcripts; giving it the task ceiling's record unscoped would have been worse, since the step total returns to 0 at every commit while the re-speaking rule assumes a measure that only climbs. The fingerprint reads directory **names** and never their contents: the brake asks whether the task set changed and never which task is active, so the task-resolution ladder keeps its single implementation. |
| `understand-write-guard.py` | PreToolUse (`Edit\|Write`) | Read-only rail for the Understand phase. Reads the phase from the task the checkout is working: the `.ai-flow/artifacts/*/state.md` whose `branch:` line names the branch currently checked out; a sheet naming another branch is another workstream's and is never read here, so the only other candidate is a single sheet that names no branch at all — a project written before the field, or a task whose claim was released when the checkout took on another (`released-branch:`, which the anchored pattern cannot read as a claim) — and failing that the ledger `.ai-flow/STATE.md`. The phase itself is read from the **first** line of that file declaring the field (label, then a colon — see the backlog protocol's `## State Files`); no other line counts, so prose that merely quotes the field declares nothing, and a phase written in any other form leaves the rail silent. A sheet that **cannot be read** is neither: it loses its `branch:` claim along with its phase, so which task resolves would change silently — the rail refuses and names it, but only where reading it could have changed the answer, since refusing on any unreadable sheet under `artifacts/` would let one stale sheet block every write. Jurisdiction is settled before any verdict, refusals included, so a write under `.ai-flow/` or outside the repository is never refused for a phase the rail could not read — an unknown phase cannot change an answer that never depended on it, and the refusal's own text names correcting the sheet as the way out. The refusal has **two** sites, because the ledger answers where no task sheet resolves: the sheet the ladder could not classify, and the resolved state file whose phase could not be read. An `.ai-flow/` that cannot be **listed** is the third: Python raises there rather than answering, and an uncaught raise leaves a `PreToolUse` hook on exit 1, which does not block — so the write went through with a stack trace printed over it. While that phase is UNDERSTAND blocks Edit/Write to any repo file outside `.ai-flow/`, judging the written path against the working directory the session declares, never the hook process's own; the block message names the file it read. A linked worktree is judged by its own state, never by an enclosing repo's. Investigation and Bash stay unrestricted. No-op in any project without an `.ai-flow/`. |
| `artifact-write-guard.py` | PreToolUse (`Write`) | A finished task document is never replaced. Refuses a `Write` naming an **existing** `.ai-flow/artifacts/<task>/understand.md`, `plan.md`, `verify.md` or `discoveries.md` — the four that hold decisions taken in earlier sessions — and the refusal names the file and names the remedy, which is to read it and **amend** it with `Edit`. There is **no exemption to declare**: a replan amends the plan artifact too, and a rail the model can open by declaring the exception is theatre. It **never reads its contents**, so the block cannot echo the decisions it just saved into the scrollback and the transcript — the same safety property the secret guard's row states. Creating one of the four is allowed: the rail is about replacement, not creation. **`state.md` is deliberately outside it** — every phase writes that file at every close, and a rail over the most-written file is the rail that gets routed around; so are the conformance manifest, everything else under `.ai-flow/`, every repo file outside it and every path outside the repository. **`Edit` is never judged**, and that jurisdiction is in the guard's own code and not in the matcher alone: this JSON is merged **by hand** into each adopter's settings, a hand-merge into the neighbouring `Edit|Write` group is exactly how a matcher widens, and a guard that could judge an `Edit` would deny the remedy it advertises. Needs neither the phase nor the task-resolution ladder — the verdict is a path test and an existence test, and nothing about which task or phase is live can change it. The existence test is `os.stat` and not `Path.exists()`, which answers `False` on a `PermissionError` and would report an artifact the guard may not look at as absent, waving its replacement through; a path that **cannot be read** is refused and named instead, per *What a guard may conclude from* below, while a genuinely absent file and a path whose parent is a file are allowed. **It is invisible to the shell**: a heredoc or `>` redirection reaches these four files with no tool call for a `PreToolUse` matcher to see, so what the rail covers is the assistant's file tools and nothing more — the reading habit is still the whole of the protection there, and for `state.md`. No-op in any project without an `.ai-flow/`. |
| `context-structure-guard.py` | PreToolUse (`Edit\|Write`) | Changing how the context mechanism works, or the shape of a file that gives a task its context, is a **declared act**. Two subjects, judged differently. A write naming the **mechanism itself** -- the shipped rulebook `protocols/context.md` or the measure `context-check.sh` -- is structural outright: there is no content half to either, and the two are matched by the shape of their own path rather than by living under any root, since the rulebook ships to `~/.claude/ai-flow/protocols/` and sits at `global/protocols/` in the engine's own checkout. A write to a **context file** -- a checkout's own `.ai-flow/steering/*.md` less `pencil-design.md`, plus `product.md` and `decisions-global.md`, which is the measure's default set and chosen for the measure's own reason, *where the files live* -- is structural only where it changes the file's **structural signature**: the ordered list of its `## ` titles and its `## Nano` block. That question is asked **the way the measure asks it** (fenced blocks skipped, HTML comments stripped, `## ` at line start, nano bullets joined with their continuations), because a guard that decided for itself what counts as a section would refuse writes the measure calls clean and pass writes it calls broken. The signature is **compared, never parsed for intent**: the guard computes what the file has and what the write would leave it with, taking the second from `content` for a `Write` and by applying `old_string`/`new_string` in memory for an `Edit`, honouring `replace_all` and treating its absence as false. An `Edit` whose `old_string` does not match, or matches more than once without `replace_all`, is allowed -- the tool refuses it anyway. **Creating** a context file is structural, which is the one place this rail departs from its sibling's *replacement, not creation* principle: a new file in the class is the strongest structural act there is, and the moment the engine itself creates one is the archive checklist's first step, already inside key 1's window. Two keys open the rail, both read from the sheet of the task this checkout is working: **`phase: **ARCHIVE**`** and the line **`structure: context`** -- what each one means, and when each is written, are `protocols/context.md`'s, which owns the rule this rail performs. **The refusal names both**, because a refusal naming one key sends the reader to a door that may be shut. **Jurisdiction is settled lexically, before the path is resolved**, and that ordering is the mirror of the sibling rail's rather than a copy of it: that rail judges what is OUTSIDE a directory, so a path it cannot resolve is correctly a pass, while this one judges what is INSIDE, so an unresolvable path lexically in the judged set is refused instead of waved through. `template/.ai-flow/` is outside the judged set by construction -- it is the engine's product, the conformance suite's business, not one project's context. The task is resolved by the ladder in the backlog protocol, **rungs 1 and 2 only**: `STATE.md` is a roster and carries neither key, so a checkout that falls to it has no declaration to read and the rail stays silent rather than refusing over a file that could never have opened it. **Where no task resolves the rail is silent** -- a deliberate hole, so an operator between tasks can repair a context file by hand; refusing instead would make hand-repair need a task opened to declare on. An input that **cannot be read** is neither: the sheet, the file to be judged, or a payload field the verdict needs is refused and named, per *What a guard may conclude from* below, and an empty `old_string` is that case wearing a usable type. **It is invisible to the shell**: a heredoc or `>` redirection reaches every one of these files with no tool call for a `PreToolUse` matcher to see. No-op in any project without an `.ai-flow/`. |
| `drift-check.sh` | Stop | Engine drift guard. Quiet while the engine source has uncommitted changes; blocks session close when an installed engine file differs from its committed HEAD, printing the exact fix. It reports **at most once per request**, and where any Stop hook already refused in that request it stays quiet for the rest of it: the payload says whether the stop is one the harness is re-delivering after a refusal, and on a re-delivery the guard exits quietly rather than turning one refusal into a loop. So a request in which a sibling spoke first can pass with this guard saying nothing at all — the report is deferred to the next request, never dropped, and it returns on every request until the divergence is gone. The payload is **parsed**, not matched as text, so a truncated or non-JSON one is absent input and absent input reports; where `python3` is unavailable no suppression happens and the guard behaves as it did before. The read is bounded and accumulates line-wise, because a Stop hook waiting for input it never receives is a hung session, and a read that waits for a delimiter loses on bash 3.2 whatever it had already taken. Where the session sits in a linked engine checkout, the message states that installing from it repoints the guard's own source and silences the guard for good once that checkout is dismantled, so it is not offered as an equivalent remedy. An installed file counts as clean when it matches **any** engine checkout's committed HEAD — the recorded clone or, when the session runs in a linked worktree of it, that worktree too; otherwise a worktree's own engine commits would read as drift, and a stale worktree would raise the opposite false alarm. No-op on remote installs, where **no clone is recorded**. A recorded path that **cannot be read** is refused and named instead: the clone is known and the guard simply could not reach the record, which is not the same fact. |
| `context-cost-note.py` | UserPromptSubmit | Session cost note, and the only hook here that **never refuses**. Measured over 285 transcripts: cache-read is ~70% of the price-weighted bill and cache-read is context size times turns, so what a turn does barely moves its cost -- only how much context it drags; sessions of 150 turns or more are 95.7% of this engine's own repository's bill. Simulated on each session's real per-turn curve with re-caching priced in, restarting every 150 turns saves **24.3%** here and **32.9%** on the project the engine is used to build. Those are the corrected figures: an earlier estimate of 51.3% modelled a restart from zero context, and turn 1 already costs 43-47k for the system prompt, the project's instructions and the tool definitions -- that floor is why the honest number is a quarter to a third. **On every prompt** it supplies the model with two measured quantities and no verdict: the context this session is carrying, and what starting over would cost — the leanest working state the session has had, which is where a fresh one lands once it has read the task's papers back, and never the bare turn-1 floor, which prices a restart that could not resume. The phase close compares them; that line is the only channel by which it ever sees them, and it is model-only, so the operator's view is unchanged. **On top of that**, at 150 main-loop turns it says once that cutting at the **next phase boundary** now pays, and again at 300, firmer, and never a third time. It names what a cut destroys rather than saying "save your state": the sheet's `## Ruled out` lines, a `hypothesis:` tested and killed and an `alternative:` rejected with its reason, neither of which is a decision *taken* and so neither of which the sheet used to hold. Two things about how it speaks are load-bearing. It **exits 0 on every path**, because blocking mid-Execute costs more than the tokens it saves. The channel is decided by who the note is addressed to: it asks for two lines to be written to a sheet, and the writer is the model, so it runs at `UserPromptSubmit` and carries **both** halves in one object (see `## Which channel reaches whom`). And it keeps **no sentinel file**: the harness records a delivered `systemMessage` back into the session's own transcript, so the hook reads its own prior note out of the file it already opens -- no path to choose, no session-versus-checkout scope to decide, nothing left behind. The model half is written back as a `hook_additional_context` record whose `content` is a **list**, which the reader joins rather than matching by accidental stringification. Turns are counted from `transcript_path` (else the newest record for this working copy), as assistant records carrying `usage`, skipping any marked `isSidechain`: a subagent's turns are not in this session's context and are 1.2% of the bill. Every failure to read or parse falls to **silence**, never to a note. No-op in any project without an `.ai-flow/`. |
| `git-safety.py` | PreToolUse (Bash) | Reports whether this repository's own protections are in place; it judges no command. The two `Never` rules live in the git hooks below, which are handed the refs and the index rather than the command's text — the guard that read that text refused documents for quoting an operation and could not be narrowed without losing protections. On a command that would record or publish something, this rail resolves the working directory the session declares and, if the repository's effective hook path is not `~/.claude/hooks/git` and it carries none of these hooks, refuses and prints the command that fixes it. A repository whose own tooling owns the hook path silences it with `git config aiflow.protection acknowledged` — an accepted gap and a silent one look identical from outside, and that is what tells them apart. Its trigger is a crude text test on purpose: a shape it misses is a reminder that does not fire, never a protection that does not run. |
| `git/pre-push` | git `pre-push` | The trunk on a remote is never rewritten and never deleted. Decides from what git reports per ref — the destination, an all-zero local sha, and whether the commit the remote holds is still an ancestor of the one being sent — so no command text is involved and no wrapping, quoting or alias changes the verdict. **The destination it compares against is the branch the remote DECLARES as its default**, read from `refs/remotes/<remote>/HEAD` and verified with `rev-parse` because `symbolic-ref` answers even for a branch that is gone, and rejected unless it points inside that remote's own namespace. Where nothing declares a default — a repository wired up by hand rather than cloned, a push addressed to a URL rather than to a remote's name, or a declaration of either wrong shape — the brake's candidates stand in, so such repositories keep exactly the coverage they had. **What is held against the brake is the candidate list and only that**: a harness row extracts `main master` from each source and fails unless the two are the same list in the same order. The resolution itself is restated rather than shared, because a shell hook cannot import Python, and it departs from the brake in two ways the hook's own header states — it asks whichever remote the push named rather than `origin`, and it does not verify the candidates locally. **The cost is stated in full rather than hidden**, and it is wider than the case that motivated it: a resolved declaration REPLACES the candidates rather than joining them, so the trunk name the remote does *not* declare stops being defended in every clone — a stale `master` beside a declared `main` is force-pushable now where it was not before. And `refs/remotes/<remote>/HEAD` is what the remote declared *at clone time*; no `fetch` or `pull` refreshes it, so a repository cloned before a default-branch rename defends the old name and accepts a force-push over the new one. `--force` and `--force-with-lease` arrive identically and both are refused: a lease guards against overwriting someone else's work, not against rewriting the trunk. The trunk is matched by exact ref name, so an ordinary branch whose path merely ends in `main` is untouched. A repository's own `pre-push` still runs, chained after this one and its verdict honoured. Bypass with `--no-verify`, which the refusal names. |
| `git/pre-commit` | git `pre-commit` | A commit never records a secret. Reads the index — **the paths the commit would record, and the lines it would add** — so a secrets file named only in the message, or sitting unstaged, is not a staging, while a key pasted into an ordinary source file no longer passes for having an ordinary name. The content half matches **fixed shapes only**: a private-key header and five provider token forms written out whole — alphabet, segment structure and length as the issuer fixes them, never a prefix with an open-ended tail, which would refuse ordinary placeholder text such as a Slack sample token in a README. Never randomness — a measure that guesses raises false alarms on fixtures and sample data, and a guard people learn to ignore protects nothing. Each pattern is written so the pattern's own text is not an instance of it, which is what keeps this guard's source and the suite that drives it committable with the guard active; exempting their paths instead would have created two files in which a real secret passed unseen. The lines are read with `--text --no-ext-diff --no-textconv --literal-pathspecs`, because a pipeline whose only answer is "matched / did not match" cannot say *I could not look*: an undiffable path, a global external-diff driver, a textconv attribute or a path beginning with `:` each returned no lines, and no lines read as clean. The refusal names the file and which kind of shape was found, and **never the matched text** — a guard that echoes the secret it caught has copied it into the scrollback and the CI log. Only additions and changes are judged: removing a secret committed by mistake must stay possible, and for the same reason an amend that merely carries forward a secret its parent already records is not re-judged, while one that adds a secret is refused. POSIX shell, no interpreter dependency: a commit hook that cannot start makes git refuse the commit. Chains to a repository's own `pre-commit`. Bypass with `--no-verify`. |

## What a guard may conclude from

**Every input a verdict concludes from is proven usable before it is concluded from.** A guard that
could not read its input has not found the input clean — it has reached no verdict at all, and the two
must never leave by the same exit. This is craft rather than ceremony: the guards here exist to say
*somebody looked*, so the one moment the claim matters is the moment it silently stops being true.

The distinction that makes the rule applicable:

- **Absent is silence by design.** No `.ai-flow/` means this is not an ai-flow project; no recorded
  clone means the engine was installed from no checkout; no declared phase means no rail to raise. Each
  guard documents its own silences in the table above, and they stay silences.
- **Unreadable is a refusal that names the file.** The input exists and the guard cannot reach it, so it
  refuses, names the file, and carries the fix. Blocking on a permission fault is an interruption; the
  alternative is a guard that reports "clean" on something nobody read.

Two traps, both of which shipped here before being reproduced and removed:

- **`-f` is true for a file whose contents cannot be read** — stat only needs the parent directory. So
  is `-d` for a directory that cannot be entered, which matters because such a directory makes the files
  inside it test as *absent*, i.e. as the designed silence. `-r` is the test that separates them **for a
  file**, and it is needed beside `-f`, not instead of it. **For a directory the bit is search (`-x`),
  not read** — and confusing the two breaks the check in both directions: mode `0400` leaves `-r` true
  while no child can be stat'ed, so an `-r` gate stays silent over the very fail-open it was added to
  close, and mode `0100` reads every child fine while an `-r` gate refuses and claims nothing was
  checked. Ask which access the guard actually performs: opening a known path needs search on its
  directories, listing one needs read as well. In Python the same fault arrives as an
  exception instead of a false answer: listing an unreadable directory raises, and an uncaught raise
  exits 1 — a code no hook event treats as blocking, so the guard fails open *and* prints a stack trace
  over whatever it was judging. Catch it and refuse; the raise is the authority, so catching it beats
  pre-testing with an access check, which is only a guess about what the next call will do.
- **A discarded exit status cannot be recovered from the output.** `awk` on an unreadable file and a
  file legitimately holding nothing both yield nothing; `grep -c` answers 1 for a legitimate "found
  none" and 2 for an error. So key on the status, captured on the line immediately after the command,
  and where a counting tool cannot report its own failure, gate on readability before it runs.

Two things this does not close, named here rather than left for the next reader to discover. A read that
fails *after* the readability test passes: where the status is free to capture, capture it and the window
shuts; where it is not, the window is accepted. And a guard that folds "could not determine" into an
existing silence for a *different* reason — the drift guard treats any non-zero from its
work-in-progress probe as work in progress — which is the same collapse one level out from the input,
and worth stating so the list is not read as exhaustive when it is not.

## Which channel reaches whom

**This section owns this fact. Every hook that carries a note cites it and restates none of it** — it was
written out longhand in six places before, three hook headers and three rows above, and two of those copies
had already drifted into saying something false.

Measured live on this harness, with distinct marks carried through a multi-turn session, because the
transcript cannot answer it: the harness writes a full-content record for a message it never shows the
model, so *recorded* and *delivered* are different facts and only a live session separates them.

| Channel | Reaches the operator | Reaches the model |
|---|---|---|
| `systemMessage` on stdout, exit 0 — at **any** event | yes | **no** |
| `hookSpecificOutput.additionalContext` at `UserPromptSubmit` | no | **yes** |
| stderr with exit 2 — only where refusing is possible | yes | yes |

Two consequences the hooks are built on. A note addressed to the **model** — cut the session, sweep the
ledger, decompose the file — must travel as `additionalContext`, so it must run at `UserPromptSubmit`; the
event and the field are two decisions and moving only one ships a note that still reaches nobody. And a
note carries **both** fields in one object, so the operator keeps seeing exactly what they saw before.

Exit 2 is not a channel a note may use: at `Stop` it costs a turn-close, and at `UserPromptSubmit` it stops
the operator's prompt from being sent. A refusal is issued only where refusing is possible.

## Registering them

**Updating from a version before the split**: `install.sh` is additive and never removes, so an existing `~/.claude/settings.json` keeps its `Stop` entry for `context-cost-note.py` after an update. That entry is dead but harmless — the hook resolves the event and no-ops at any event that is not its own — so nothing breaks if you leave it. Remove it if you want the registration to read as what it is.

The installer does this for you: `install.sh` (init with tooling, or `update`)
merges `settings.hooks.json` into the `hooks` key of `~/.claude/settings.json`
idempotently via python3, preserving your other settings and your own hooks.

The two git hooks are registered differently, because git does not read
`settings.json`: the installer copies them to `~/.claude/hooks/git`, sets their executable
bit explicitly — a hook without it is skipped by git with a hint and nothing else — and points
`core.hooksPath` there for every repository on the machine. **An existing global hook path is
reported and left alone**, never replaced: someone who already manages hooks globally has a
setup of their own, and taking it away to install one is not an improvement. A repository that
sets its own hook path (a hook manager typically does) displaces them; `git-safety.py` is what
says so, per repository, instead of letting the gap pass unmentioned.

To do it by hand (e.g. python3 unavailable), merge `settings.hooks.json` into the
`hooks` key of `~/.claude/settings.json` yourself. The commands use `$HOME` so they
are portable across machines.

Hooks are independent — install only the ones you want. They do nothing harmful
outside an ai-flow project (`check-state-size.sh` is a no-op without `.ai-flow/`).
